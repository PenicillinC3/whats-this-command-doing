# Claude Code

Before submitting a Bash or PowerShell tool call that might prompt for permission, follow the shared rules in `SKILL.md` and supply a plain-language `description` when the tool exposes that field. Claude Code can decide whether to ask for permission after the call is submitted. Describe the command in the shell it actually uses.

- Use a short statement that names the action and target and includes the reason and biggest consequence. For example, “Clear the files generated by the last build by deleting the `dist` folder and everything inside it. The files won't go to the Recycle Bin.”
- When the tool has no suitable field or the interface is known to hide the description, use the separate-message fallback in `SKILL.md` if the host permits it.
- Permission-prompt comments are supplied by the user when answering a prompt and then sent back to Claude; they are not a field for Claude to pre-fill.
- Hooks such as `PermissionRequest` or `PreToolUse` are separate integrations. Do not claim that this Skill makes permission decisions, intercepts every request, or rewrites the UI.
- Never use a hook or command wrapper to silently approve an action as a substitute for explaining it.

For local use, install this skill in `<project>/.claude/skills/whats-this-command-doing/` or `~/.claude/skills/whats-this-command-doing/`. Follow current Claude Code documentation for skill discovery and permission behavior.
