# What’s This Command Doing?

[English](README.md) | [简体中文](README.zh-CN.md)

What’s This Command Doing? is a Codex and Claude Code skill that explains command-line approval requests in the user's language. It covers Bash, Zsh, sh, Fish, PowerShell, Windows Command Prompt, and other terminal environments. It describes the requested action, purpose, approval scope, and material consequences without replacing the host's permission system.

## Install

Copy the `skills/whats-this-command-doing` directory from this repository to one or both locations:

- Codex project skill: `.agents/skills/whats-this-command-doing/`
- Claude Code project skill: `.claude/skills/whats-this-command-doing/`

For user-wide installation, copy the folder to Codex's `~/.agents/skills/whats-this-command-doing/` or Claude Code's `~/.claude/skills/whats-this-command-doing/`. Keep the folder name `whats-this-command-doing` and the included `SKILL.md`. Restart or start a new session if the host does not discover the skill immediately.

## Use

- Let the host discover the skill automatically when relevant.
- Invoke it explicitly with `$whats-this-command-doing` in Codex or `/whats-this-command-doing` in Claude Code where slash skill invocation is supported.
- To use the rule in one project, paste the block below into that project's `AGENTS.md` (Codex) or `CLAUDE.md` (Claude Code).

## Apply across projects

Copy the full rule below and add it using one of these methods. If you already have a command approval rule, replace it and keep your other instructions.

### Desktop apps

- **Codex / ChatGPT desktop.** Open **Settings → Personalization → Codex instructions** and paste the rule into the text box.
- **Claude Desktop.** Open **Settings → General → Instructions for Claude** and paste the rule into the text box.

### Instruction files

Add the rule to the relevant file. Create the file if needed.

- Codex reads `~/.codex/AGENTS.md` (Windows: `C:\Users\<you>\.codex\AGENTS.md`).
- Claude Code reads `~/.claude/CLAUDE.md` (Windows: `C:\Users\<you>\.claude\CLAUDE.md`).

### Rule to copy

```markdown
### Explain each terminal approval

Before submitting a terminal command that can prompt for approval, write an explanation in the user's current language for someone who has never used a terminal or written code. Apply the whats-this-command-doing skill when available. Follow this rule even if the skill is missing or not loaded.

Say what you want to do, which file, folder, website, or account it affects, and why it helps with the current task. Explain the consequences that could change the user's decision, including what will be deleted, replaced, or sent and where it will go. If the action needs extra access, explain what this approval grants. State what you cannot verify when it matters. Use everyday words. The explanation must make sense with the command hidden. “May I run this command?” and the command alone are insufficient.

Before submitting, put that explanation in the command tool's user-facing approval field, such as Codex's justification or Claude Code's description when available. Write the description before calling any tool that decides whether to ask for permission after submission. Check the text each time, including retries. If the tool has no suitable field or the app is known to hide it, explain the action immediately before the native request when the app permits a separate message. Follow the app's permission rules and wait for the user's decision. Never run the command early or approve it yourself.
```

Start a new session after saving the rule. If you already installed the skill, replace that copy with the updated folder. Try asking it to draft an explanation for deleting the project's `dist` folder without running the command. The explanation should be clear even if you cover up the command. For example:

> May I delete the `dist` folder and everything inside it to clear the files generated by the last build? The deleted files won't go to the Recycle Bin. I haven't checked whether the folder contains anything you saved yourself.

The rule guides the assistant. If an app generates its own generic prompt, what appears in the approval dialog still depends on that app.

## Remove

Delete the installed `whats-this-command-doing` skill directory. If you added the rule to desktop settings, `AGENTS.md`, or `CLAUDE.md`, remove it there too.

## Validation

The behavioral cases in [`evals/cases.md`](evals/cases.md) are writing and review scenarios. They must not execute destructive commands, send data, or run unknown scripts.
